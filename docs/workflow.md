# 从一句讲解到一段动画

先选一个观众看完能够复述的问题。例子：“为什么 Transformer 的训练可以并行，生成却仍有先后？”

## 1. 写能听懂的口播

每句话承担一个主要解释。适合阅读的长段落，应拆成适合听的短句。必要术语在出现时解释；数字只保留帮助理解的部分。

示例的 `narration.txt` 一行对应一个场景，`project.json` 中的场景顺序与它一致。

## 2. 把解释变成动作

| 口播中的关系 | 可以怎样表现 |
|---|---|
| 前一步的结果决定后一步 | 词块依次亮起，结果传到下一个位置 |
| 不同位置直接交换信息 | 从同一组输入出发，画出跨位置连接 |
| 按不同权重汇总 | 用不同分量的信息流，汇入同一个输出 |
| 后续内容尚未生成 | 保留空位，每产生一个词才开启下一步 |

保持同一对象的颜色与身份。位置、路径、数量或状态变化应服务于机制解释。

## 3. 先生成声音，再安排时间

本例整段调用微软语音，取得声音和词级时间点。对齐程序根据这些时间点生成字幕和场景边界；一个词级事件内部的字符时间以插值估计。

`project.json` 的 `anchors` 指定画面需要跟随的关键词。它们必须出现在对应行的口播里。例如，`Decode` 的开始时间用于安排输出词块逐个出现。

时间轴决定每段何时开始；场景内的动作由各自代码安排。字幕跟随语音，而不是按全文字数平均分配时长。

## 4. 绘制与合成

示例的 `frame(t)` 返回某个时刻的 RGB 图像。渲染程序按每秒 30 帧调用它，把画面交给 FFmpeg，再与配音合成。

中文字体、图形和转场在本地绘制。没有额外背景音乐。最终画布为 1080×1920，文字与主要对象为竖屏阅读留出空间。

## 5. 改动时保留可复用的部分

- 只改连线、颜色、布局：运行 `render`，复用配音和时间轴。
- 改口播、音色、语速：运行 `prepare` 或 `build`，重新取得对应声音和时间点。
- 新增或删去场景：一起修改口播行、场景配置及 `render.py` 中的绘图函数。
- 更换科学主题：复用配音、对时和合成组件，重新设计主题对应的图形关系。

## 与 AI 编程助手协作的提示词

下面是一段可自行改写的制作要求：

> 围绕一个明确问题制作 1080×1920 的科学讲解动画。先把口播拆成场景，说明每个场景中谁在变化、信息从哪里到哪里、结果是什么。以输入文稿和原始资料为依据；没有依据的几何或数字省去。用 Python 编写持续变化的机制动画，保持对象颜色和身份一致。使用整段配音的词级时间点安排字幕与场景。最终交付视频、口播、声音、字幕、时间轴和可编辑动画代码。

向任何在线 AI 或语音服务提交内容时，应使用你愿意发送到该服务的文稿。
